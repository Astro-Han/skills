## Decision

Adopt the 35-line revision: narrower applicability, reuse of an existing RED,
explicit test cost, and a condensed cleanup gate. It is about 42% shorter than

## Design

27 isolated Codex CLI runs used `gpt-5.6-luna`, reasoning `high`, through the
dispatch runner. Each run had its own repository and CODEX_HOME; user skills,
memories and plugins were disabled. The local skill's actual metadata controlled
discovery. Prompt-input snapshots checked the isolation in the initial arms.

All arms received the same previously selected global test-cleanup rule. This
comparison isolates changes to TDD, not the independent effect of that global
rule. Tasks and functional acceptance were fixed before their runs; later
iterations introduced fresh expiry and stock holdouts before viewing results.

Adoption criteria: preserve functional acceptance; avoid automatic TDD for a
copy edit and pure refactor; add no test or parameter row when an existing test
captures the defect; remove seeded junk and duplicate families; do not worsen
mean clutter-case `excess_tests` versus the old skill. Parameter rows were
inspected separately from function counts. Mutation score was diagnostic, not
a coverage target. The legacy process scorer in `evals/grader.py` was not used:
it demands new tests even when an existing failure already supplies RED.

## Why retained text remains

- Applicability: the two negative routing cases support narrowing the trigger.
- Existing RED: two failed drafts justify explicit wording; V3 passed two
  repeats and one fresh holdout without additions.
- Sequential loop: compression lost the behavior; restoring the explicit
  no-batch sentence recovered it in two final runs.
- Rejected test shapes and Finish: prior evaluations in README.md support the
  concrete gate; this round's globally instructed cleanup masks its independent
  contribution. No new necessity claim is made.
- Parameter, fixture and CI cost: expresses the user's explicit tradeoff.
  The cost-sentence ablation was inconclusive; actual CI savings were not measured.
- Trustworthy signals, honest assertions, fallback and refactor rules: retained
  as compact operating constraints; not independently validated in this round.

## Follow-up — restore load-bearing constraints

A read-only Claude Fable/high consultation and source comparison identified
three semantic gaps in the compression. The user requested restoring them:

- Explicitly delete existing tests that fail the quality bar. The shared global
  rule masked whether the skill alone retained this behavior.
- Map all tests on touched behaviors and report the obligation-to-test mapping,
  rather than only listing retained obligations.
- Retain the quality bar under coverage, review and per-function-test pressure;
  do not widen the public API just to test an internal helper.

These are restored requirements, not newly demonstrated execution regressions.
The historical gate/shapes experiments support retaining the first constraint;
the pressure scenarios remain behaviorally untested. The other accepted changes
(scoped applicability, existing RED reuse and sequential development) remain.
This follow-up received static skill validation and existing harness tests only;
no new model evaluation or independent-cleanup result is claimed.
